ОПИСНАНИЕ СТРУКТУРЫ:

### **PL-GL/** — Главная папка проекта

Всё приложение структурировано в рамках одной общей папки **PL-GL**, где есть несколько основных разделов:

---

### **client/** — Клиентская часть (Frontend)

В этой папке находится всё, что связано с клиентским интерфейсом, включая стили, изображения, шрифты, скрипты и страницы.

- **assets/** — Статические файлы (иконки, изображения, шрифты):
  - **images/** — Все изображения, которые используются на сайте (например, фотографии, картинки, фоновые изображения).
  - **icons/** — Папка для SVG иконок, используемых в интерфейсе.
  - **fonts/** — Шрифты, используемые на сайте (например, custom шрифты).
  
- **styles/** — Стили CSS для различных частей приложения:
  - **global.css** — Общие стили для всего сайта, например, для body, шрифтов, и других базовых настроек.
  - **header/** — Стили, относящиеся к верхнему меню (header), включают:
    - **banner.css** — Стили для баннера на странице.
    - **navbar.css** — Стили для навигационной панели (navbar).
  - **auth/** — Стили для страниц авторизации (вход, регистрация):
    - **login.css** — Стили для страницы входа.
    - **register.css** — Стили для страницы регистрации.
  
- **scripts/** — Скрипты JavaScript:
  - **main.js** — Главный файл скриптов, который инициализирует поведение сайта, а также может импортировать другие модули.
  - **components/** — Переиспользуемые компоненты:
    - **googleAuth.js** — Скрипт, реализующий логику авторизации через Google.
    - **navbar.js** — Скрипт, управляющий поведением навигационного меню (например, открытие/закрытие, управление ссылками).
  - **auth/** — Скрипты, связанные с процессами аутентификации:
    - **login.js** — Логика для страницы входа.
    - **register.js** — Логика для страницы регистрации.
    - **forgotPassword.js** — Логика для восстановления пароля.

- **pages/** — HTML-страницы:
  - **index.html** — Главная страница приложения.
  - **auth/** — Страницы авторизации:
    - **login.html** — Страница для входа пользователя.
    - **register.html** — Страница для регистрации пользователя.

---

### **server/** — Серверная часть (Backend)

Эта папка содержит всю логику, связанную с серверной частью вашего приложения. Здесь находятся конфигурации, обработчики маршрутов, модели для работы с базой данных и т.д.

- **config/** — Конфигурация приложения, включая настройки базы данных и ключи API:
  - **db.js** — Подключение к базе данных (например, PostgreSQL).
  - **googleAuth.json** — Файл с ключами для интеграции авторизации через Google (например, OAuth ключи).
  
- **controllers/** — Логика обработки запросов (контроллеры для различных маршрутов):
  - **authController.js** — Контроллер для обработки логики авторизации и регистрации пользователей.
  - **userController.js** — Контроллер для работы с данными пользователей (например, получение информации о пользователе, обновление данных и т.д.).

- **routes/** — Определение API-маршрутов:
  - **authRoutes.js** — Маршруты для авторизации (например, логин, регистрация).
  - **userRoutes.js** — Маршруты для работы с данными пользователей (например, получение/обновление профиля).

- **middleware/** — Промежуточные обработчики (middleware) для выполнения логики на этапе обработки запросов:
  - **authMiddleware.js** — Проверка наличия и валидности JWT токена, защита маршрутов (например, если пользователь не авторизован, он не может получить доступ к защищённым маршрутам).

- **models/** — Модели, связанные с базой данных, для работы с данными пользователей:
  - **User.js** — Модель пользователя, описывающая структуру таблицы пользователя в базе данных, а также методы для работы с этой таблицей.

- **server.js** — Главный серверный файл, который запускает приложение, слушает порты и обрабатывает HTTP запросы.

---

### **database/** — Файлы, относящиеся к базе данных

Папка для хранения SQL файлов и миграций, которые будут использоваться для создания и обновления базы данных.

- **migrations/** — SQL-файлы миграций, которые будут применяться для изменения структуры базы данных (например, создание новых таблиц, изменение существующих).
- **seeders/** — Тестовые данные, которые могут быть использованы для наполнения базы данных в процессе разработки.
- **schema.sql** — Файл с описанием структуры базы данных (например, создание всех таблиц и их связей).

---

### **Корневые файлы проекта:**

- **package.json** — Файл, описывающий зависимости проекта (например, библиотеки, которые нужны для работы серверной и клиентской части).
- **package-lock.json** — Лок-файл зависимостей, генерируемый при установке зависимостей (обеспечивает консистентность версий пакетов).
- **.gitignore** — Файл, в котором указано, какие файлы и папки должны быть проигнорированы системой контроля версий Git (например, папка **node_modules/**).
